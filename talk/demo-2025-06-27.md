## Last time

* In the last demo session I showed the direct benefits of deterministic
  simulation testing (DST) with respect to test coverage of the system under
  test (SUT);

* Analogy: DST is like a *wind tunnel* for distributed systems

  + By making the SUT deterministic and simulating the network and passage of
    time while injecting faults we get fast and non-flaky end-to-end tests;

  + Failures on CI can be reproduced locally from a seed, which helps
    debugging.





















## Today

* Time-travelling debugger enabled by determinism of the SUT

* Analogy: the blackbox recorder in an aeroplane

* Two primary use cases:
  1. Debug failures found by DST;
  2. Debug errors in production.

* Demo: debugging a DST failure






















## How does it work?

### Recall how DST works:

```
+---------------------+               +--------------------------------------+
|           Simulator |               |                                 SUT  |
|                     |               |                                      |
|          +------+   |               |                                      |
|          | PRNG |   |               |                                      |
|          +------+   |               |                                      |
|                     |               |                                      |
| +----------+        |               |       +----------------------------+ |
| |          |        |               |    ⋰  |                  Node   ⋰  | |
| | Messages |        |     Input     |       |                            | |
| |          +----------------------->|  +---------------------------+     | |
| |          |        |               |  |                   Node    |     | |
| +----------+<-----------------------+  |                           |-----+ |
|                     |    Outputs    |  |                           |       |
| +---------------+   |  (messages,   |  |                           |       |
| |   Journal     |   |   logging,    |  +---------------------------+       |
| +---------------+   |   state diff) |                                      |
+---------------------+               +--------------------------------------+
```


### Errors in production use cases

* Keep circular buffer of inputs
* Dump buffer to disk on errors for later offline debugging sessions
* Relies on snapshot of the state

```

                   +-----------------------------------------+
                   |                                   Node  |
                   |                                         |
                   |                                         |
                   |                           _.-----._     |
                   |   +---------------+     .-  Disk   -.   |
                   |   |      Cirular  |     |-_       _-|   |
                   |   |       buffer  |     |  ~-----~  |   |
                   |   |               |     |           |   |
                   |   |    .-----.    |     `._       _.'   |
                   |   |   / \ 1 / \   |        "-----"      |
      Input        |   |  / 6 \ / 2 \  |            ^        |
```

## Conclusion

* Determinism in the SUT isn't just useful for testing, but also for debugging
* Time-travelling debuggers are easy to write in this setting
